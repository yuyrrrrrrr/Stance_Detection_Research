  ---

  为什么这样设计（贯穿全局的几个原则）

  1. 单一事实来源（Single Source of Truth）
  标签映射（labels: [支持,反对,中立]）、输入模板（"{target} [SEP] 
  {text}"）、路径、超参只在 base.yaml + format.py 定义。训练 dataset.py 和线上
  app.py 都走同一个
  build_input()，从根本上防止「训练与推理模板不一致」这类经典线上事故。

  2. 数据「三层不重叠」+ 只读上游
  raw（只读）→ interim（归一化）→ processed（划分/增强）
  层层派生，中间产物由脚本再生所以全部 .gitignore，只留 .gitkeep
  占位。manifest.json 记录每个源 CSV 的 sha256，保证可复现。

  3. 研究口径先冻结、再编码
  README 第九节把「Macro-F1 主指标 / 中立 F1 关键 / 5 种子 / Wilcoxon + Holm /
  严格零样本」写成硬约定，check_protocol.py
  把这些约定变成可执行守卫，eval/stats.py
  实现统计检验。设计意图是「事后不改口径」。

  4. 关注点分离到配置而非代码
  数据增强预算（da.yaml）和 DG
  损失权重（dg.yaml）与基础训练（base.yaml）分开，开关默认全
  false——先跑无增强基线，再逐模块消融，符合论文消融实验的需求。

  5. src/ 是可安装包，不是散落脚本
  pyproject.toml 显式声明 8 个 packages，所有入口用 python -m src.xxx
  调用，scripts/ 只做编排。这样 import 路径稳定（from src.data.constants import 
  ...），IDE 跳转和单元测试都干净。

  ---

  一句话总结这个骨架的设计意图：把「研究可复现、协议可守卫、训练/推理一致」三个
  目标工程化——上游数据只读、中间产物可再生、配置单一事实、口径冻结成脚本。这也是
